## 二、签名算法怎么破的

### 两代签名：网页版 `_r` → PC 客户端 sign.dll

**历史脉络**：之前（dump 项目）只破了**网页版签名 `_r`**（`signature.py`，`api2.jiakaobaodian.com` 单域名），当时不需要 sign.dll，靠 `_r` 就能拉题。**sign.dll 是这次 PC 客户端 21 域名签名才第一次深挖**——多域名要各自 secret，必须调 dll。

**`_r`（时间戳校验参数，网页版 + PC 客户端都要）**：
```
n = abs( parseInt( time * random * 1e4 ) )     // 大随机数
t = n各数字之和 + len(n)                        // 校验位
_r = "1" + str(n) + str(t).zfill(3)             // 1开头，补零到3位
```
这个逻辑从 renderer.js 模块里挖出来（`Gj` 函数），Python 的 `gen_r()` 是它的复刻。**关键**：`_r` 要参与签名，所以必须生成正确。

**`sign`（主签名）**：
```
signInput = path + "?" + baseParams + "&" + bizParams
sign = SignUrl(signInput, secret)      // sign.dll 导出的函数
```
- `SignUrl` 是 `sign.dll`（dist/static/lib/sign/）导出，输入 `path?query` 和 secret，返回签名
- **前提**：要先 `Init(sign.db)`（rc==1 才算初始化成功）
- baseParams 固定值（`_appUser/1234567890`、`_deviceId`、`_version 8.22.0`…），拼进 query 一起签名

### sign.dll 逆向（不反编译也能破）

**没反编译它**——直接 ffi 调 dll 是"黑盒复用"，最快。但为了搞懂原理，用 Go 符号表挖出了算法：

**sign.dll 身份**：Go 编译（`rt0_go`/`goexit`/`runtime.g`/`internal/cpu` 等 Go runtime 符号），x86 32位，1.6MB。

**从 pclntab 抠函数名**（Go 默认带符号表，没 strip）：
```
main.Init                初始化
main.SignUrl / SignUrl0 / SignUrl1   签名三层
main.PKCS5UnPadding      AES 解密垫片
main.aesIv / main.aesKey  AES 密钥+IV
main.checkFileHash       sign.db 文件校验
main.decrypt / md5File   解密 + MD5
main.getSigningVersion   签名版本
```

**算法真相**：
1. **签名是 MD5**（`crypto/md5` + `md5File` + `EncodeToString`），不是 AES
2. **AES 是解密 sign.db 用的**：sign.db 是**加密密钥库**，Init 时用 `aesKey`+`aesIv` 解密（`PKCS5UnPadding`）拿到真正的签名密钥
3. `checkFileHash` 校验 sign.db 完整性——防止别人改密钥库

**没继续深挖**：aesKey/aesIv 是 main 包全局变量，常数值在二进制 .data 节（非 ASCII）。与其反编译 AES，不如**抓运行时内存**——Init 解密后密钥表已经在进程内存里，attach dump 即可。

### 签名机 = 调 sign.dll 的封装

客户端 NW.js 能 require ffi 调 dll，所以签名机就是一个 node 脚本：
```
sign_runner/run.js  ← 读 params.json → require('ffi') → lib.Init(sign.db)
                    → lib.SignUrl(input, secret) → 写 result.json
```
Python 采集端 ↔ run.js 交互（文件传参）：
1. Python 写 `params.json`（path + biz + 可选 extra）
2. 启动 exe（main 指向 run.js）跑签名
3. 等 `result.json` 出来 → 拿 fullUrl → kill 进程

**批量模式**：`{'mode':'batch','reqs':[{host,path,biz}...30个]}`，一次 exe 签 30 个请求，快一个数量级。

**单例限制**：params.json/result.json 是单例文件——**同一时间只能有一个进程用签名机**。双进程抢会互相覆盖，必须单实例。

### 签名机的坑
- **UTF-8 BOM**：PowerShell `Set-Content` 写 JSON 带 BOM → node `JSON.parse` 报 "Unexpected UTF-8 BOM"。改用 Python `open().write(json.dumps().encode('utf8'))` 无 BOM 写
- **main 指向**：采集时 main 指向 run.js（不弹 GUI），采集完必须恢复 `./dist/index.html`，否则客户端打不开
- **进程不退出**：NW.js node 模式 net server 不保活事件循环 → TCP 常驻方案放弃，改 per-request 启动
- **慢**：per-request 1-2 秒/请求 → 全国几百请求几十分钟。改成**批量模式**一次启动签 30 个

## 三、题库数据怎么解密的（car.db）

PC 客户端运行时从官方下载最新全量库到本地：
```
C:\Users\lenovo\AppData\Local\Jiakaobaodian\User Data\Default\tikuUpdate\db\car.db
```
SQLite 67MB，`t_question` 6406 题。

**题干/解析/关键词是加密 blob**，解密逻辑在 renderer.js `decodeData()`：
```js
const n = Buffer.from("_jiakaobaodian.com_");   // XOR key，19字节
for (var t=0; t<e.length; t++) e[t] = e[t] ^ n[t % n.length];  // 逐字节循环 XOR
```
Python `decrypt.py` 复刻同款，`decrypt(key, blob) = bytes[i] ^ key[i % len(key)]`。

**表结构**：`t_question`(6406题) + `t_chapter`(119章节) + `t_media`(1526媒体，media_content blob 直接写图片/视频) + `t_exam_rule`(地区考试规则) + `t_chapter_question`(章节-题目映射+areacode)。

**坑**：
- mediaKey 曾因 export 丢弃 → 2052 题假象（图全没了）。逐字段对源库校验才抓出
- PNG 被硬编码 .jpg → 4 图错引。看文件头判断真实格式

## 六、登录态数据

重学题库（relearn/question-list）、VIP 解析（vip/question-explain）、会员端点要 authToken，但登录被**网易易盾验证码**挡（captchaId `6f92317b6e7d4f4faa77a360d65826c5`）。

**authToken 从哪来**：只在 Pinia store 内存（`userInfo.authToken`），localStorage 不存 → 文件里读不到。但**登录后每个请求 URL 都带 authToken**。

**方案**：`inject_auth.js` hook 客户端 XHR，从请求 URL 偷 authToken → 写 `sign_runner/auth_token.txt` → 签名机读它注入 baseParams。
- 启用：package.json 加 `"inject_js_start": "sign_runner/inject_auth.js"`
- 前提：用户手动登录一次客户端（过验证码）。**之后完全自动化，无需用户**。

## 十三、已知行为 / 注意事项（速查）

1. **签名机单例**：params.json/result.json 是单例，同一时间只允许一个进程签名
2. **风控安全线**：5 并发 + 0.15-0.2s 间隔 ≈ 5 QPS。30 并发触发"异地登录保护"
3. **auth_key 5 分钟过期**：视频直链不能预取，必须实时调 API
4. **authToken 只活内存**：Pinia，不进 localStorage，靠 inject_auth.js 偷
5. **package.json main 切换**：采集时 `sign_runner/run.js`，平时 `./dist/index.html`
6. **sceneCode**：顺序练习=101，错题重学=102
7. **cursor 整数陷阱**：cursor=0 时 `if(cursor)` 为 false → 漏采，必须 `if(cursor is not None)` 或用 `hasMore`
8. **FIFO 队列饿死**：大批量任务要 LIFO
9. **JSON 无 BOM**：PowerShell 写文件带 BOM 会让 node 崩
10. **GBK 控制台**：Python 中文输出在 GBK 终端报错 → `PYTHONIOENCODING=utf-8`
